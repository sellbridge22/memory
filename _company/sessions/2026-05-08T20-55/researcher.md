## 🛠️ Mini-Module 진단 결과 시뮬레이션 데이터셋 (Developer API 테스트용)

CEO님의 지시에 따라, 개발자가 Mini-Module의 핵심 로직과 UI 연동(특히 경고 게이지 애니메이션 및 임계점 표시)을 테스트할 수 있도록 세 가지 수준의 가상 데이터 세트를 구조화했습니다. 이 데이터는 시간 경과에 따른 **변화 추이**를 중심으로 설계되어 API 검증에 최적화되었습니다.

---

### 📊 데이터셋 포맷 정의 (Schema)

모든 시나리오에 공통으로 적용되는 핵심 지표 및 단위입니다:

| Metric Name | 설명 | 측정 단위 | 정상 범위 |
| :--- | :--- | :--- | :--- |
| `cognitive_load_score` | 현재 인지 부하 점수. (높을수록 과부하) | 0 - 100점 | Low: 30~50 / Medium: 60~80 / High: >90 |
| `task_switching_cost_rate` | 작업 전환 시 발생하는 효율 저하율. (낮을수록 안정적) | % (0% ~ 25%) | Optimal: <5% / Warning: 10~15% / Critical: >20% |
| `sustained_attention_index` | 유지 가능한 집중력 지수. (점수가 높고 기울기가 완만할수록 우수) | 점수/시간 (Score/Hr) | Low: 안정적 상승 곡선 / Medium: 급락 구간 발생 / High: 급격한 하락세와 변동성 극대화 |
| `alert_level` | 진단 결과로 도출되는 최종 경고 레벨. | String (Low, Medium, High) | 필수 필드 |

### 🟢 Scenario 1: Low Critical Alert Level (최적의 흐름 상태)

**[상황 설명]**: 사용자가 몰입(Flow State) 상태를 유지하고 있으며, 작업 효율성이 안정적으로 관리되고 있음. **(→ 서비스 신뢰도 확보 및 기능 소개에 활용)**

| 지표 | 시간 0분 (시작) | 시간 30분 (최고점) | 시간 60분 (종료) | 개발자 테스트 포인트 |
| :--- | :--- | :--- | :--- | :--- |
| `cognitive_load_score` | 35점 | 42점 | 38점 | 점수 변화의 완만한 곡선. '안정성' 강조. |
| `task_switching_cost_rate` | 3% | 4% | 3.5% | 낮은 수치를 유지하며, 안정적인 상태를 보여줌. |
| `sustained_attention_index` | 높음 (기울기: +0.8) | 최고점 도달 후 완만하게 하락 (기울기: -0.2) | 여전히 높은 수준을 유지 (기울기: 0) | '지속 가능성'이 핵심 메시지. |
| **`alert_level`** | Low | Low | Low | 시스템 정상 작동 상태임을 명시적으로 보여줌. |

---

### 🟡 Scenario 2: Medium Critical Alert Level (주의 단계 - 개선 필요)

**[상황 설명]**: 사용자의 집중력이 몇 번의 방해 요소(Distraction)로 인해 저하되기 시작했음. 즉각적인 경고는 아니지만, **개선 도구 도입을 유도하기 적절한 지점.**

| 지표 | 시간 0분 (시작) | 시간 30분 (경고 발생) | 시간 60분 (저점 기록) | 개발자 테스트 포인트 |
| :--- | :--- | :--- | :--- | :--- |
| `cognitive_load_score` | 50점 | **78점 (임계치 근접)** | 72점 | 특정 지점에서 급격한 상승(Spike) 후 미세하게 하락하는 패턴. 경고 게이지의 '노란색 점등' 연동 테스트 필수. |
| `task_switching_cost_rate` | 8% | **14%** | 12% | 뚜렷한 증가 추이. 이 지점에서 "전환 비용 관리가 필요합니다" 메시지 노출 테스트. |
| `sustained_attention_index` | 중상 (기울기: +0.5) | 급격히 하락 시작 (기울기: -1.0) | 여전히 낮은 수준 유지 (기울기: -0.5) | 명확한 **하강 추이**를 보여주어 '시스템 오류' 인지 유도. |
| **`alert_level`** | Low $\rightarrow$ Medium | Medium | Medium | 경고 레벨 변경에 따른 UI/UX 변화(색상, 애니메이션) 테스트가 핵심. |

---

### 🔴 Scenario 3: High Critical Alert Level (위험 단계 - 즉각 개입 필요)

**[상황 설명]**: 인지 시스템이 심각하게 과부하되었으며, 생산성 저하가 임계점을 넘어섰음. **(→ Mini-Module Pro Plan 구매 강제 유도에 최적화)**

| 지표 | 시간 0분 (시작) | 시간 15분 (위기점) | 시간 30분 (시스템 부하) | 개발자 테스트 포인트 |
| :--- | :--- | :--- | :--- | :--- |
| `cognitive_load_score` | 85점 (이미 높음) | **98점 (최고 위험)** | 92점 | 최고점에서 급격한 반등(Rebound Failure)을 보여주어 '시스템 실패' 느낌 극대화. 경고 게이지의 '빨간색 최대치' 연동 테스트 필수. |
| `task_switching_cost_rate` | **>25% (측정 불가)** | **최대 폭발** | 23% | 수치를 초과하여 아예 측정 자체가 어려워진 상황을 데이터로 표현. 가장 큰 '손실' 메시지($XXX)와 연동되어야 함. |
| `sustained_attention_index` | 매우 낮음 (기울기: -1.5) | **거의 0에 수렴** | 급격한 변동성 폭발 | 데이터 자체가 의미를 잃을 정도로 불안정한 상태를 시각화해야 함. |
| **`alert_level`** | Medium $\rightarrow$ High | **Critical Alert!** | Critical Alert! | 시스템 전체가 경고하는 듯한 강렬하고 자극적인 UI/UX 연출이 필요함. |
