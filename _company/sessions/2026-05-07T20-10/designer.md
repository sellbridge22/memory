### 🧪 섹션 1: 핵심 인터랙션 컴포넌트별 QA 매트릭스 (Component-Specific Test Cases)
다음은 모든 상태 변화 지점(State Change Point)에서 반드시 통일성을 유지해야 하는 Critical Path 요소들입니다. 각 항목의 성공 기준을 명시합니다.

| 컴포넌트 | 트리거/상태 (Trigger/State) | 예상되는 사용자 행동 | 필수 QA 검증 사항 (Pass Criteria) | 애니메이션 사양 및 로직 |
| :--- | :--- | :--- | :--- | :--- |
| **데이터 입력 필드** | 1. 정상 범위 (< 0.6 Threshold) | 평이한 정보 입력 | 테두리 색상: `#333333` (딥 그레이). 글리치/경고 효과 없음. | - |
| | 2. 경고 임계값 도달 (0.6 ~ 0.8) | 데이터 변화 추적 | **테두리 깜빡임:** 네온 레드 (`#FF3B30`)가 주기적으로 점멸(Strobe Flash, 5Hz). 글리치 아티팩트 미세 노이즈 오버레이 시작. | **Timing:** Strobe Cycle (200ms ON / 800ms OFF). **Effect:** VHS Noise Layer (opacity 10%) 활성화. |
| | 3. 시스템 과부하 임계값 (> 0.8) | 진단 결과 확인/위기감 주입 | **강제 경고:** 테두리 전체에 네온 레드 글리치 배너(`SYSTEM OVERLOAD: CRITICAL`)가 고정 배치. 입력 필드 자체의 텍스트 색상이 불안정한 것처럼 깜빡여야 함. | **Animation:** Strobe Flash (10Hz, High Contrast). **Effect:** Jitter 효과(좌우 픽셀 단위 떨림) 최대치 적용. 배경에 네온 레드/블랙 대비의 글리치 패턴이 전역적으로 오버레이 되어야 함. |
| **CTA 버튼** | 1. 기본 상태 (Inactive) | 초기 진단 유도 | 평범하고 전문적인 느낌의 다크 모드 디자인 유지. | - |
| | 2. 활성화/클릭 시 (Active/Click) | 다음 단계로 이동 요구 | **시각적 압력:** 버튼을 누르는 순간, 버튼 영역 주변에 네온 레드 에너지 코어가 폭발하듯 확산되면서 클릭 애니메이션이 발생해야 함. | **Animation:** Radial Burst Effect + 100ms 빠른 Opacity Fade-in/out. (기존 '버튼' 느낌 탈피) |
| **임계값 경고 오버레이** | 시스템 과부하 상태 진입 시 | 정보 인지 및 위협 감지 | *오버레이의 존재 자체가 가장 중요.* 화면 전체를 덮는 반투명 네온 레드/검은색 그리드 패턴. | **Animation:** 낮은 빈도의 노이즈(Noise)와 주기적인 '데이터 손실'을 암시하는 짧고 날카로운 글리치 스파이크 효과를 무작위로 발생시켜야 함. (지루함 방지) |
| **데이터 시각화 그래프** | 데이터가 임계값을 넘어서는 순간 | 경고의 증거 제시 | 단순한 라인 그래프가 아닌, 마치 *시스템 자원이 역류하는* 것처럼 보이는 애니메이션으로 변환되어야 함. | **Animation:** 에너지 코어(Core Energy) 하강 게이지처럼 디자인하고, 네온 레드 색상과 함께 데이터 손실 시뮬레이션 효과를 적용해야 함. (데이터 = 생명력 개념 부여) |

### ⚡️ 섹션 2: 통합 테스트 플로우 (End-to-End User Flow QA)
Mini-Module의 전체 사용자 여정(User Journey)을 따라가며 경고 시스템이 일관되게 작동하는지 검증합니다.

1.  **[진단 시작] -> [데이터 입력]:** 사용자가 첫 데이터를 입력할 때 (상태 1), 아무런 경고 없이 부드럽게 진행되어야 합니다.
2.  **[경계 감지/전환점 A]:** 데이터가 임계값(0.6)에 도달하는 순간, 시스템 전체의 배경 노이즈와 UI 요소들이 **동시에** 미세하게 떨리거나 깜빡여야 합니다 (Strobe Flash & Jitter 동시 적용). 이는 '시스템이 문제를 감지하기 시작했음'을 사용자에게 암시해야 합니다.
3.  **[위기 고조/전환점 B]:** 데이터가 과부하 임계값(0.8)에 도달하면, 모든 경고 요소(테두리, 오버레이, 그래프 등)의 강도와 빈도가 **급격하게 증폭(Exponential Increase)**되어야 합니다. (예: 깜빡임 주기가 200ms에서 50ms로 단축).
4.  **[진단 결과 페이지]:** 최종적으로 'SYSTEM OVERLOAD' 배너가 고정될 때, 이전에 발생했던 모든 애니메이션 요소(노이즈, 글리치)의 최대치가 한 번에 폭발하듯 연출되어야 합니다 (The Grand Finale Glitch).

### 📈 섹션 3: 기술적 제약 및 개발자 핸드오프 사항
*   **애니메이션 성능 최적화:** 위 모든 효과(Strobe, Jitter, Glitch)는 GPU 기반으로 구현되어야 하며, 모바일 환경에서도 프레임 드랍 없이 최소 30 FPS를 유지해야 합니다. (성능 테스트 필수).
*   **색상 코드 관리:** 네온 레드 (`#FF3B30`)와 데이터 청록색 (`#00FFFF`)의 대비율(Contrast Ratio)을 모든 경고 상황에서 최대치로 유지하도록 사양화합니다.
*   **에러 핸들링:** 네트워크 연결 실패나 필수 데이터 누락 등의 오류가 발생할 경우, 일반적인 "Error 404" 메시지 대신, **"SYSTEM FAILURE: DATA STREAM LOST. RECONNECTING..."** 형태의 글리치 처리된 에러 페이지로 대체해야 합니다.
