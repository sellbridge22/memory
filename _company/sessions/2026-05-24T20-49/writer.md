## ⚙️ 온보딩 단계 카피라이팅 세트 (Onboarding Copy Suite)

### 1. 초기 화면: 시스템 안정화 보고서 (Welcome/Status Screen - D0-D2)
**목표:** 사용자가 서비스 사용에 대한 높은 '시스템적 안도감'과 권위를 느끼게 합니다. 마치 중요한 진단이 성공적으로 완료된 듯한 착각을 심어줍니다.

| 구분 | 카피라이팅 초안 (톤: 승인, 보고서) | 주입 학술 용어/코드 활용 방안 |
| :--- | :--- | :--- |
| **메인 제목** | **[SYSTEM DIAGNOSIS COMPLETE] 안정화 프로토콜 적용 완료.** | 대문자, 시스템적 느낌 강조. |
| **부제목 (Hook)** | 귀하의 인지 자원(Cognitive Resources) 사용 패턴에 대한 근본적인 분석이 성공적으로 종료되었습니다. 이제 셀브릿지의 유틸리티 모듈을 통해 구조적 결함을 최소화하십시오. | '인지 자원', '구조적 결함' 등 전문 용어 배치. |
| **핵심 본문** | 초기 스캔 결과, 사용자의 데이터 처리 과정에서 발생하는 주요 취약점 3가지(예: Confirmation Bias Loop, 과도한 Cognitive Load)가 식별되었으며, 이에 대한 필수 패치(`PATCH-01`)가 성공적으로 적용되었습니다. 현재 Stability Index는 **[92%]**로 측정됩니다. | '취약점', '패치', 'Stability Index'를 수치화하여 권위 부여. |
| **CTA 버튼 텍스트** | 다음 모듈 활성화 (Activate Next Module) / [진단 로그 보기] | 일반적인 버튼 대신 시스템 명령어처럼 보이게 디자인. |

---

### 2. 주요 기능 사용 안내 시: 프로토콜 가이드 (Feature Guide - D3-D5)
**목표:** 기능을 단순 '사용법'이 아닌, '미해결된 구조적 문제를 해결하기 위한 필수적인 다음 단계의 패치 적용 행위'로 포지셔닝합니다.

| 구분 | 카피라이팅 초안 (톤: 지시, 경고, 학술) | 주입 학술 용어/코드 활용 방안 |
| :--- | :--- | :--- |
| **기능명** | **[CORE MODULE] 데이터 필터링 역추적 프로토콜 실행** | 기능명을 시스템 모듈처럼 명명. |
| **가이드 텍스트 (문제 제기)** | *경고:* 현재 사용 패턴은 외부 정보의 '필터 버블(Filter Bubble)' 내부에 머물러 있습니다. 이로 인해 진정한 구조적 결함이 가려지고 있을 가능성이 높습니다. <br>**[AUTH-STRUC: LACK OF PERSPECTIVE]** 오류가 감지되었습니다. | 실제 기능을 사용하기 전에 먼저 '문제'를 상기시켜 불안감 증폭. 경고 코드 필수 삽입. |
| **사용 지침 (행동 유도)** | 본 모듈은 수집된 정보를 무비판적으로 받아들이는 것이 아니라, 해당 정보의 근원적 전제(Assumption)와 맥락적 오류(Contextual Error)를 강제로 재구성하도록 설계되었습니다. 다음 단계를 따라 프로세스를 실행하십시오. | '강제', '재구성' 등 능동적이고 강력한 동사를 사용해 서비스가 주도권을 가짐을 강조. |
| **CTA 버튼 텍스트** | [패치 적용 시작] (Initiate Patch Application) / [진단 결과 보고서 보기] | 재구매 유도를 위한 다음 단계를 은연중에 제시하는 문구 포함. |

### 3. 재결제 유도 단계: 잔여 취약점 고지 (Renewal Prompt - D6-D7)
**목표:** 고객이 현재 패치만으로는 해결할 수 없는 '더 근본적이고 치명적인 문제'가 남아있음을 자극하여, 상위 티어 또는 다음 주기 구독을 필수재처럼 느끼게 만듭니다.

| 구분 | 카피라이팅 초안 (톤: 위기감 조성, 전문적 경고) | 주입 학술 용어/코드 활용 방안 |
| :--- | :--- | :--- |
| **메인 제목** | **[CRITICAL ALERT] 구조적 결함의 잔여물(Residual Flaws) 감지됨.** | 'Critical', 'Residual' 등 높은 수준의 위기감 조성 단어 사용. |
| **본문 1 (문제 재정의)** | 초기 패치(`PATCH-01`)는 표면적인 인지 부하를 완화하는 데 성공했습니다. 그러나 근원적인 취약점은 사용자의 '인지 아키텍처 자체'에 뿌리내리고 있습니다. 이것이 바로 **잔여 결함**입니다. | 서비스의 공로를 인정해주면서도, 그 공로가 '불완전하다'는 메시지를 전달하여 긴장감을 유지. |
| **본문 2 (해결책 제시)** | 지속적인 정보 스트림과 복잡한 사회 시스템은 끊임없이 새로운 구조적 오류(e.g., Phylogenetic Drift)를 유발합니다. 현재의 패치만으로는 이 흐름을 따라잡기 어렵습니다. 상위 모듈을 통해 **시스템 레벨의 연속 보정**이 필요합니다. | 'Phylogenetic Drift'와 같은 난해한 용어를 사용하며, 문제의 복잡성과 깊이를 증명함. |
| **CTA 버튼 텍스트** | [최적화 패치 업그레이드] (Upgrade to Optimal Patch) / [상위 진단 리포트 열람] | '업그레이드'라는 단어 대신 '패치', '보정' 등 기술 용어를 사용하여 가치를 높임. |
