## 📊 핵심 산출물: Mini-Module용 공학적 과부하 데이터 시각화 컴포넌트 설계서 (V1.0)

CEO 지시사항을 충족시키기 위해, 인지 및 시스템적 과부하를 증명하는 학문적 근거(심리학/공학) 3가지와 이를 직접 데이터 시각화에 활용할 수 있는 구체적인 방법론을 아래와 같이 정리했습니다. 이 자료는 Designer가 즉시 UI 컴포넌트 개발에 사용할 수 있도록 '데이터 포인트' 중심으로 구성되었습니다.

### 1. 인지 부하 모델 기반: 주의 자원 고갈 그래프 (Attention Resource Depletion Graph)
*   **근거 이론:** 제한된 심리적 에너지(Cognitive Load Theory, Working Memory Model). 개인의 노력이 시스템에 가하는 지속적인 '처리 비용'을 시각화합니다.
*   **주요 Pain Point 정의:** 정보 과부하로 인한 의사 결정 피로 및 주의력 분산.
*   **[디자인 컴포넌트 목표]**: **"당신의 집중 자원은 이미 X% 고갈되었습니다."**라는 경고를 시각화하여 즉각적인 해결책(Pro Plan)의 필요성을 부여합니다.

| 데이터 요소 | 측정 지표 (Metric) | 수치 범위/설명 | 시각화 방법 (Visualization) |
| :--- | :--- | :--- | :--- |
| **주요 축** | 인지 부하 점수 (Cognitive Load Score, CLS) | 0점(정상) $\to$ 100점(임계 초과) | 곡선 그래프 및 임계점 표시 (Threshold Line) |
| **핵심 지표 A** | 평균 작업 전환 비용 (Switching Cost Index, SCI) | 사용자가 한 앱/작업에서 다른 작업으로 이동할 때 발생하는 시간적 손실 (예: 15% 증가). | 막대 그래프 또는 누적 영역 차트. |
| **핵심 지표 B** | 잔여 주의 자원 (Available Attention Units) | 시간에 따른 감쇠(Decay) 곡선 형태의 게이지. | 경고색 애니메이션 게이지 (황색 $\to$ 적색). |
| **권위 키워드** | Working Memory Capacity, Cognitive Debt, Attentional Bias | - | 소제목 또는 툴팁에 활용. |

### 2. 시스템 결함 모델 기반: 시간-노력 비효율성 진단 (Time-Effort Inefficiency Audit)
*   **근거 이론:** 공학적 신뢰성 분석(FMEA, Failure Mode and Effects Analysis). 개인의 일상 루틴을 하나의 '시스템'으로 간주하고, 결함 지점(Failure Point)과 그로 인한 손실 비용을 계산합니다.
*   **주요 Pain Point 정의:** 시간 관리가 아닌 **'구조적 비효율성'**에 의한 노력 낭비. (시간의 가치 저하).
*   **[디자인 컴포넌트 목표]**: "당신이 매일 잃고 있는 돈(기회 비용)을 수치로 증명"하여 $9.99$ 번들 구매를 설득합니다.

| 데이터 요소 | 측정 지표 (Metric) | 수치 범위/설명 | 시각화 방법 (Visualization) |
| :--- | :--- | :--- | :--- |
| **주요 축** | 시스템 결함 빈도 (Failure Frequency Rate, FFR) | 하루 평균 발생 횟수. | 점 그래프 또는 알림 메시지 카운트. |
| **핵심 지표 A** | 비효율성 누적 손실 비용 (Cumulative Loss Cost, CLC) | (시간 낭비 시간 $\times$ 평균 시간당 가치). 구체적인 $XXX$ 금액 제시 필수. | 가장 크게 강조되어야 할 '손실 경고' 배너. |
| **핵심 지표 B** | 임계 결함 발생률 (Critical Failure Rate, CFR) | 일정 기간 내 시스템 붕괴를 초래하는 치명적 패턴의 빈도. | 게이지 또는 빨간색 플래그 아이콘. |
| **권위 키워드** | Time Drain, Systemic Vulnerability, Opportunity Cost Analysis | - | 부제 및 설명란에 사용. |

### 3. 심리학 기반: 복잡성 처리 한계치 도달 경고 (Complexity Threshold Warning)
*   **근거 이론:** 인간의 본질적인 정보 처리 용량 제한(Cognitive Tunneling, Overchoice Paradox). 너무 많은 선택지나 복잡한 정보를 다룰 때 발생하는 마비 상태를 이용합니다.
*   **주요 Pain Point 정의:** 해결해야 할 문제가 많아져 오히려 아무것도 시작하지 못하는 **'결정 장애 루프'**에 빠짐.
*   **[디자인 컴포넌트 목표]**: 사용자가 스스로 '복잡성 처리의 한계점'을 인지하게 하여, 시스템이 제공하는 단순하고 명확한 구조적 해결책(Pro Plan)으로 유도합니다.

| 데이터 요소 | 측정 지표 (Metric) | 수치 범위/설명 | 시각화 방법 (Visualization) |
| :--- | :--- | :--- | :--- |
| **주요 축** | 정보 복잡성 점수 (Information Complexity Score, ICS) | 0점(단순 명료) $\to$ 100점(혼란/마비). | 스케일 바 또는 게이지 형태. |
| **핵심 지표 A** | 필수 인지 자원 대비 정보량 비율 (IRR Ratio) | 사용자가 처리해야 하는 정보의 양 / 실제로 활용 가능한 인지 자원의 비율. (높을수록 위험). | 파이 차트 또는 비율 그래프. |
| **핵심 지표 B** | 결정 회피 지수 (Decision Avoidance Index, DAI) | 결정을 미루는 패턴이나 반복적인 검색/확인 행동의 빈도. | 시간 흐름에 따른 패턴 분석 그래프. |
| **권위 키워드** | Overchoice Paradox, Cognitive Tunneling, Decision Fatigue | - | 전문성을 강조하는 용어 목록으로 활용. |
