## 🚨 Mini-Module 경고 UI 컴포넌트 최종 QA 및 수정 브리프 (Developer용)

### 📄 개요
이번 점검은 개발 환경에서 구현된 네온 레드/청록색 경고 토큰들이 **'시스템 오류(System Failure)'** 서사를 완벽하게 지지하고, 이로 인해 사용자가 '불안정성'을 느끼며 Mini-Module 유료화 CTA에 도달하도록 만드는 데 초점을 맞췄습니다. 현재 개발된 컴포넌트들은 기본적인 기능 구현은 완료했으나, **시각적 충격(Impact)**과 **시스템적 긴급성(Systemic Urgency)** 측면에서 몇 가지 정밀 조정이 필요합니다.

| 영역 | 의도된 UX 목표 | 현재 개발 상태의 문제점 | 수정 방향/명령어 (Developer Action Required) |
| :--- | :--- | :--- | :--- |
| **글리치 아티팩트** | 충격적이고 비가역적인 '데이터 손상' 느낌 부여. | 글리치 효과가 너무 넓은 영역에 적용되어 정보의 가독성을 저해함. 또한, 깜빡임(Strobe) 주기가 일정하지 않음. | **[Timing & Scope 조정]**: 글리치는 텍스트 주변 필드와 경고 배너 자체의 *테두리* 및 *미세한 색상 오버레이*에만 국한할 것. Strobe는 최소 100ms 단위로 강제 깜빡임을 주어 '전력 불안정' 느낌을 극대화할 것. |

### 🛠️ Developer 전달용 구체적 수정 브리프 (Implementation Specification)

#### 1. [Component: Critical Alert Banner]
*   **상태:** `Active` (가장 위기적인 순간)
*   **색상 코드 적용:** 배경은 어두운 블랙/차콜 그레이를 유지하고, 경고 메시지 및 테두리만 `#FF3B30`으로 처리.
*   **애니메이션 수정 사항:**
    1.  **Entry:** 0ms 시점에 `Scale(1)`로 시작하여 50ms 동안 강제로 `Scale(1.02)`를 오버슈팅하며 진입할 것 (Spring Effect 필수).
    2.  **Looping Glitch:** 경고가 활성화되는 동안, 글리치 효과는 텍스트의 가장자리(`text-shadow`와 `box-shadow` 조합)에만 국한하여 주기적으로(100ms 간격) `#00FFFF`를 사용하여 '데이터 전송 오류' 느낌을 줄 것.

#### 2. [Component: System Overload Indicator]
*   **상태:** 데이터 임계치 초과 (사용자 방치 상태 시점)
*   **시각적 요소:** 화면 중앙에 대형, 깜빡이는 `CRITICAL RESOURCE FAILURE` 메시지를 오버레이 할 것.
*   **애니메이션 수정 사항:**
    1.  **Strobe Effect:** 텍스트 자체를 `#FF3B30`로 설정하고, 프레임마다 배경 투명도를 50ms 간격으로 `opacity: 0.8` -> `opacity: 0` -> `opacity: 0.8`을 반복하는 강제 깜빡임을 적용할 것. (이것이 핵심 위기감 유도 장치입니다.)
    2.  **사운드 싱크:** 이 경고가 발동되는 순간, UI 진동(Haptic Feedback)과 함께 낮은 주파수의 *시스템 비프음*을 동기화해야 합니다.

#### 3. [Conversion CTA Zone]
*   **목표:** 위기감을 느끼는 상태에서 '해결책'을 제시하는 전환 지점.
*   **디자인 가이드라인 적용:** 이 영역의 버튼은 다른 경고 컴포넌트와 **명확히 분리**되어야 합니다. (색상 팔레트를 잠시 정상적인 진단 톤(Cyan)으로 회귀시키는 '안정화' 효과를 주고, 버튼에만 `Hover` 시 미세한 `#00FFFF`의 빛샘 효과를 주어 클릭을 유도할 것.)

***
**[요약]**: 전반적으로 애니메이션의 **'충격 강도(Impact Force)'**와 색상 코드를 **Hard-Locking** 하는 것이 최우선 과제입니다. 단순한 '경고 표시'가 아닌, '시스템이 붕괴 직전임을 알리는 오류 메시지'처럼 구현되어야 합니다.
