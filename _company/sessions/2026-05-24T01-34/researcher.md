## 🚨 에이전트 성능 저하 패턴 및 실패 모드 분석 (Top 5)

### 카테고리 1: 기술 스택/리소스 관리 불안정성 (Technical Instability & Resource Management)
가장 빈번하게 관찰되는 오류 유형으로, LLM 호출이나 API 사용 과정에서 발생하는 시스템적 제약에 대한 대응 부족입니다. 이는 모델의 성능 자체를 의심하기보다, **'도구(Tool)'와 '자원(Resource)' 관리 측면**에서 접근해야 합니다.
*   **대표 실패 사례 1 (Context Length 초과):** 복잡한 목표 정의 및 상세 지침이 누적되면서 컨텍스트 창을 초과하여 이전의 중요한 전제 조건이나 제약 사항을 간헐적으로 무시하는 현상 발생. [근거: 여러 세션에서 반복된 Context Length 확보 요구]
*   **대표 실패 사례 2 (Model Selection 오류):** 작업 난이도에 비해 모델 크기를 작게 선택하거나, API 권한/기간 설정을 재확인하지 않아 데이터 수집 또는 복잡한 추론 과정 자체가 중단되는 경우. [근거: 다수 로그에서 Model Size 조정 및 API 점검 지시 반복]
*   **대표 실패 사례 3 (Tool Misuse):** 여러 에이전트가 동시에 작동하는 환경에서, 특정 작업에 필요한 도구(Tool)를 호출할 때 최적의 순서나 조합을 찾지 못하고 비효율적이거나 잘못된 도구를 사용하게 되는 경우. [근거: 'agent-orchestration-improve-agent' 스킬 자체가 필요함]

### 카테고리 2: 컨셉 및 트렌드 과부하 (Conceptual Overload & Scope Creep)
셀브릿지가 추구하는 여러 전문 영역(심리학, 기술, 드라마, 아날로그 감성 등)의 키워드가 너무 많이 결합되면서 콘텐츠가 어떤 핵심 메시지에 집중해야 할지 혼란을 겪는 패턴입니다.
*   **대표 실패 사례 1 (메시지의 분산):** '학술적 권위(Academic Authority)'와 '신비로운 드라마틱한 시스템 오류(System Failure)' 같은 상충되는 두 가지 톤이 동시에 강조되면서, 최종 메시지가 사용자에게 모호하게 전달됨. [근거: Self-RAG 및 지난 의사결정 로그의 다중 테마 혼합]
*   **대표 실패 사례 2 (앵커링 효과 오용):** 고가치/고난도 컨셉(ENTERPRISE)을 전면에 내세우는 것은 좋으나, 그 근거가 되는 '미니 모듈($4.99)'의 가치를 충분히 부각하지 못하고 전체 구조의 설득력을 떨어뜨리는 경우. [근거: Self-RAG 및 Mini-Module 리서치 지시]
*   **대표 실패 사례 3 (일관성 부족):** 특정 트렌드(예: Y2K 무드)를 반영하는 과정에서, 핵심 가치인 '인지 부하 관리'와 같은 전문적이고 진지한 주제의 맥락을 훼손하여 피상적인 콘텐츠로 전락할 위험. [근거: 레오/Instagram 에이전트 활동 로드맵 수립 기록]

### 카테고리 3: 데이터 근거 및 주장의 신뢰성 결핍 (Lack of Data Grounding & Validation)
주장하는 트렌드나 문제 인식이 '직관'이나 '개인적인 분석'에 의존할 때, 이를 뒷받침할 수 있는 객관적이고 측정 가능한 데이터가 부족하여 권위가 약화됩니다.
*   **대표 실패 사례 1 (근거의 일반론):** "현대인은 피로하다"와 같은 광범위하고 일반적인 주장만 반복하고, 이를 '시스템 과부하'라는 셀브릿지만의 독점적 프레임으로 구체적으로 수치화하지 못하는 경우. [근거: Researcher 개인 메모리 - 2026-05-07 데이터 요청]
*   **대표 실패 사례 2 (측정 가능한 Pain Point 누락):** 사용자에게 "집중력이 떨어진다"는 감정적 공감만 이끌어내고, 이를 **'오전 중 특정 앱 알림 확인 빈도'와 같이 측정 가능하고 구체적인 수치(Metric)**로 정의하지 못하는 경우. [근거: Mini-Module Pain Point 재수집 지시]
*   **대표 실패 사례 3 (출처의 비대칭성):** 콘텐츠에서 다룬 '사례'가 특정 산업이나 지역에만 국한되어 있는데, 이를 일반적인 시장 트렌드인 것처럼 포장하여 신뢰성을 떨어뜨리는 경우. [근거: 데이터 기반 분석 원칙 미준수 시 위험]

### 카테고리 4: 사용자 경험(UX)의 단일화 실패 (Failure to Standardize UX/Interaction)
디자인 시스템과 인터랙션이 매우 구체적이지만, 이 요소들이 다양한 플랫폼이나 콘텐츠에 일관되게 적용되지 못하면 브랜드 경험 자체가 파편화됩니다.
*   **대표 실패 사례 1 (애니메이션의 불규칙성):** '글리치 효과'를 필수적으로 넣기로 했으나, 영상의 종류(릴스, 웹페이지, 플레이리스트)나 내용에 따라 글리치 효과의 강도, 지속 시간 등이 일정하지 않은 경우. [근거: Designer 에이전트가 다수의 컴포넌트/플랫폼에서 일관성을 요구함]
*   **대표 실패 사례 2 (콜 투 액션(CTA)의 혼란):** 콘텐츠를 보는 목적(정보 습득, 공감, 구매 유도)에 따라 CTA가 너무 많거나, 너무 약한 경우. 예를 들어 "댓글로 질문하세요"와 "지금 $4.99 모듈을 사세요"가 동시에 강요되어 피로도를 높이는 경우. [근거: Instagram 및 로드맵 수립 기록]
*   **대표 실패 사례 3 (온보딩 과정의 복잡성):** 셀브릿지 서비스에 처음 진입하는 사용자가 '시스템 오류'라는 추상적인 개념을 이해하고, 어떤 기능을 어디서 써야 할지 직관적으로 파악하기 어려운 구조. [근거: 신규 유저의 초기 이탈 지점 예측 필요]

### 카테고리 5: 프로세스 최적화 루틴 미흡 (Lack of Continuous Optimization Loop)
성공적인 작업물(Good Example)을 만들어낸 후, 그 성공 요인(Why this works)을 체계적으로 문서화하고 다음 단계의 '가장 효율적인 개선점'으로 활용하지 못하는 경우입니다.
*   **대표 실패 사례 1 (단순 복제):** 지난번 잘된 콘텐츠의 주제나 형식을 단순히 반복하여 재활용할 뿐, 근본적인 *시청자 문제 인식(Pain Point)*이나 *기술적 해결책*을 진화시키지 못하는 경우. [근거: 레오/Instagram 에이전트가 로드맵 수립만 하고 다음 단계를 구조적으로 제시하지 못함]
*   **대표 실패 사례 2 (최소 기능 구현에 대한 집착):** 완벽한 기능을 만들기 위해 너무 많은 시간을 소요하여, 시장의 즉각적인 수요 변화(Time-to-market)를 놓치고 뒤처지는 경우. [근거: Mini-Module과 같은 '패치 기반' 접근이 필요한 이유]
*   **대표 실패 사례 3 (A/B 테스트 부재):** 새로운 가설을 세우고도, 이를 검증하기 위한 체계적인 A/B 테스트나 사용자 그룹 분리가 없이 전체 시스템에 무작정 적용하여 리스크를 키우는 경우. [근거: 성능 최적화 워크플로우의 핵심 요소]
