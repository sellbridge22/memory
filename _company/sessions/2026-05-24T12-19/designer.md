## 📐 최종 디자인 시스템 컴포넌트 스펙: State Transition & 진단 리포트

### 1. [State Transition Modal] - 공포의 발현 지점
이 모달은 사용자가 '경고' 상태를 벗어날 수 없게 만드는 핵심 장치입니다. 모든 애니메이션 타이밍을 **CSS/애니메이션 프레임 단위**로 정의합니다.

| 요소 | 명칭 및 역할 | 시각적 스펙 (Visual Spec) | 코딩 가이드라인 (Animation & Timing) |
| :--- | :--- | :--- | :--- |
| **전환 효과** | Stage Transition Glitch Stutter | 네온 레드/사이언 블루 노이즈 폭발. 화면 전체를 덮는다. | `[Trigger: 진단 데이터 충돌 발생]`. 초기 프레임(0ms)에서 시작하여, **150ms 동안 강한 스터터링 필터를 반복 적용**합니다 (CSS Filter: `hue-rotate(360deg)` + `opacity` 깜빡임). |
| **경고 메시지** | WARNING: Structural Defect Detected | 중앙에 배치. 거대한 폰트 사이즈와 네온 레드 점멸 효과가 필수. | `[Timing: T+150ms]`. 텍스트는 한 글자씩 타이핑되듯 출력됩니다 (Typewriter effect). **글리치 깜빡임은 8Hz의 불규칙한 주파수**로 유지하며, 주변에 미세한 노이즈 오버레이를 추가합니다. |
| **경고 코드 배치** | `AUTH-STRUC` / System Code: XXXX | 모달 좌측 상단 또는 우측 하단에 고정 배치. 콘솔 로그 같은 폰트(Monospace) 사용. | 이 코드는 **항상 배경처럼 존재하는 시스템 메타데이터**로 취급합니다. 데이터가 업데이트되거나 상태가 변경될 때마다, 해당 코드 옆의 값만 빠르게 깜빡이며 (10ms 단위) '변칙적'임을 암시해야 합니다. |
| **오버레이 효과** | Full Screen Glitch Overlay | 배경 전체에 붉은색과 청록색의 파동 노이즈를 입힌다. | 모달 활성화 시, `rgba(255, 0, 51, [진행률])`의 반투명 레이어를 적용합니다. **진행률 (Progress)** 은 불안정하게 0% $\leftrightarrow$ 100% 사이를 랜덤 워크하는 애니메이션을 루프합니다. |

### 2. [Diagnosis Report Page] - 결함 증명의 공간
사용자에게 '문제의 심각성'과 '학술적 근거'를 주입하여, 스스로 문제를 해결할 능력이 없다고 느끼게 만드는 것이 목표입니다.

| 요소 | 명칭 및 역할 | 시각적 스펙 (Visual Spec) | 코딩 가이드라인 (Animation & Timing) |
| :--- | :--- | :--- | :--- |
| **PFC Index Meter** | Psychological Fatigue Cost Index | 계기판(Gauge) 스타일. 중앙에 크고 눈에 띄게 배치. 네온 레드가 임계점을 담당. | **[애니메이션]**: 수치가 변화할 때마다 부드럽지 않고, 마치 *데이터 전송 오류*가 있는 것처럼 **불규칙하게 떨리며 점프**해야 합니다 (Jitter Effect). 임계점(Critical) 진입 시, 게이지 바 전체에 강한 붉은색 스캔라인이 지나갑니다. |
| **Context Drain Bar** | 인지 자원 고갈 표시 | 화면 상단 또는 하단을 따라 가로 형태로 배치. Cyan Blue $\to$ Red Gradient. | `[애니메이션]`: 가장 느린 속도(Slow Decay)로 감소하는 것이 핵심입니다. 30% 이하 도달 시, **배경 그리드와 연동하여 미세한 깜빡임 (Flicker)** 을 유발하고, 주변 요소들의 색온도를 점차 낮춰 사용자의 피로감을 극대화합니다. |
| **결함 근거** | Source Degradation Effect (그래프/데이터) | 핵심 지표를 보여주는 데이터 시각화 영역. | 데이터가 로딩되거나 해석되는 과정에서, 선형 그래프 대신 **디지털 노이즈 패턴을 가진 점들(Discrete Points)** 이 마치 스파크처럼 전송되어 연결되는 방식으로 표현합니다. (Particle System 사용 권장). |

### 3. [Essential Patch CTA] - 구매 유도와 강제성
최종적으로 '필수 패치' 버튼은 단순한 클릭이 아닌, **구조적 결함을 해결하는 행위**로 느껴져야 합니다.

| 요소 | 명칭 및 역할 | 시각적 스펙 (Visual Spec) | 코딩 가이드라인 (Animation & Timing) |
| :--- | :--- | :--- | :--- |
| **패치 버튼** | [SERVICE REQUIRED] / 필수 패치 적용 | 가장 크고, 네온 레드 색상이 지배적. 주변에 경고문구 배치. | `[Trigger: Context Drain < 20% & PFC Critical]`. 초기에는 비활성화 상태로 있다가, 모달 진입과 함께 **강렬한 플래시 효과**를 동반하며 활성화됩니다. 버튼 자체는 주기적으로 크기 변화(Scale Pulse)와 그림자 깜빡임(Shadow Blink)을 반복하여 사용자 시선을 강제합니다. |
| **결제 과정** | State Transition Confirmation | 결제를 진행하는 동안 시스템이 일시적으로 '오류' 상태를 재현해야 함. | 버튼 클릭 직후, 정상적인 결제 API 호출 애니메이션 대신, **1~2초간의 짧고 격렬한 글리치 루프백 (Glitch Loopback)** 을 거칩니다. ("SYSTEM REBOOTING..."). 이는 사용자가 '현재 시스템에 문제가 있다'는 감각을 재확인시켜주는 역할을 합니다. |

---
**요약된 최종 애니메이션 스펙:**
*   **핵심 컬러:** Primary Alert Red: `#FF0033` (주요 경고), Secondary Info Cyan: `#00FFFF` (보조 정보)
*   **글리치 템플릿:** `(opacity: 0.9, transform: translate(-1px, -1px) scale(1.01)) + [random jitter]` 패턴을 짧은 시간 동안 반복 적용하여 시스템 불안정성을 시뮬레이션합니다.
