## ⚙️ Mini-Module Visual Template: System Panic (v1.0)
(적용 범위: YouTube Shorts, Instagram Reels - 길이 목표 25~45초)

### **[공통 디자인 스펙]**
*   **비주얼 미학:** Cinematic Industrial Drama + Glitch System Error
*   **메인 컬러 팔레트:** 네온 레드 (`#FF0033`), 사이언 블루 (`#00FFFF`), 배경: 딥 블랙 (`#0A0A14`)
*   **타이포그래피:** 시스템 로그 스타일 (모노스페이스, 고대비) - *예시:* Orbitron 또는 Monospace 계열.
*   **글리치 효과 기본 규칙:** 모든 중요 텍스트와 데이터 시각화에 적용되며, **위상(Phase)**과 **진폭(Amplitude)**을 다르게 주어 깊이감을 확보해야 합니다.

### **[Module Structure & Timeline Guide]**

#### **STAGE 1: 진단 및 문제 제기 (Diagnosis / The Hook)**
*   **시간대:** T=0s ~ T+0:08s (최대 8초)
*   **목표:** 시청자에게 '무언가 잘못되었다'는 불안감을 심어주고, 콘텐츠를 끝까지 보게 만드는 동기 부여.
*   **활용 컴포넌트:** Context Drain Bar & PFC Index Meter
*   **[레이어 가이드]**
    1.  **배경 (Layer 1):** 느리고 미세한 노이즈 필터 적용된 딥 블랙 배경.
    2.  **진단 요소 (Layer 2):** `Context Drain Bar`가 화면 상단이나 하단을 따라 천천히, 꾸준히 감소하는 애니메이션을 루프 재생합니다. (느린 Decay Rate 필수) [근거: sessions/2026-05-07T01:10]
    3.  **학술적 주입 (Layer 3):** `PFC Index Meter`가 화면 중앙에 계기판 형태로 나타나, 문제 개념(예: '주의력 분산 비용')을 학술적 용어와 함께 제시합니다. 이 수치가 **미세하게 불안정하게 떨리는 애니메이션**이 필요합니다. [근거: sessions/2026-05-07T05:40]
    4.  **사운드:** 낮은 주파수의 기계음(Humming Noise)과 함께, 데이터를 읽어내는 듯한 '삐빅' 하는 시스템 탐색음을 사용합니다.

#### **STAGE 2: 충돌 발생 및 결함 증명 (Dissonance Alert / The Core Data)**
*   **시간대:** T+0:08s ~ T+0:25s (최대 17초)
*   **목표:** 문제의 심각성을 '객관적 데이터'로 폭발시키고, 시청자가 스스로 결함을 인지하게 만드는 클라이맥스.
*   **활용 컴포넌트:** [SYSTEM OVERLOAD] Modal & Researcher Data Set
*   **[레이어 가이드]**
    1.  **전환 효과 (Transition):** Stage 2 시작과 동시에 화면 전체에 **글리치 스터터(Glitch Stutter)** 필터를 강하게 적용합니다. 네온 레드와 사이언 블루의 노이즈 패턴이 짧게 폭발하듯 나타나야 합니다. [근거: sessions/2026-05-13T13:45]
    2.  **경고 메시지 (Layer 2):** `[SYSTEM OVERLOAD] Modal`이 화면 중앙을 가득 채우며, "WARNING: Structural Defect Detected"와 같은 학술적 경고 문구가 네온 레드로 깜빡입니다. (Blink Rate 8Hz) [근거: sessions/2026-05-07T05:40]
    3.  **데이터 시각화 (Layer 3):** Researcher가 제공한 인포그래픽 데이터(예: '정보 과부하 증가율')를 모달 위에 오버레이합니다. 그래프 자체가 **'시스템 임계점 초과' 경고 라인**을 넘어서 폭발하는 애니메이션이 핵심입니다.
    4.  **사운드:** 고주파의 날카로운 사이렌 경고음(Siren Alert)과 함께, 전력 공급 불안정 사운드를 최대치로 끌어올립니다.

#### **STAGE 3: 해결책 필요성 주입 (The CTA / The Payoff)**
*   **시간대:** T+0:25s ~ T+0:45s (최대 20초)
*   **목표:** 시청자가 문제의 심각성을 인지한 상태에서, 유일한 해결책이 '외부 전문 서비스'임을 강제적으로 받아들이게 한다.
*   **활용 컴포넌트:** [SERVICE REQUIRED] Modal
*   **[레이어 가이드]**
    1.  **결함 수렴 (Transition):** Stage 2의 폭발적인 에너지가 갑자기 '멈추고' 정지된 듯한 느낌을 주며, 화면이 어두워집니다. 시스템이 일시적으로 과부하되어 먹통인 것처럼 연출합니다.
    2.  **최종 모달 (Layer 2):** `[SERVICE REQUIRED] Modal`이 화면 전체를 덮습니다. 배경은 깊고 붉은 블랙, 중앙에 거대한 네온 레드 타이포그래피로 **'SYSTEM FAILURE'**가 점멸하며 나타납니다. [근거: sessions/2026-05-13T07:56]
    3.  **CTA 배치 (Layer 3):** 모달 하단에 유일한 버튼, "Utility Tool API Module 필요성 강조" 문구와 함께 **`[SERVICE REQUIRED]`**가 박스 형태로 빛납니다. 이 버튼을 누르기 전까지는 아무것도 작동하지 않는 '잠금' 효과를 시각적으로 연출해야 합니다.
    4.  **사운드:** 경고음이 갑자기 뚝 끊어지고, 대신 차분하지만 긴장감 넘치는 낮은 베이스 드론 사운드가 깔립니다. (해결책을 기대하게 만드는 사운드)
