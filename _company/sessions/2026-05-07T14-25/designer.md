## 🚨 Mini-Module System Alert v2.0: 개발자용 스펙 시트 (Developer Spec Sheet)

**목표:** 사용자에게 '개인의 노력 부족'이 아닌 '구조적 시스템 과부하'임을 느끼게 하는 고긴장감의 인터랙션 경험 제공.
**핵심 색상 팔레트:**
*   Primary Warning: Neon Red (`#FF3B30`)
*   Secondary Glitch: Cyan/Blue Shift (`#00FFFF` -> `#1A00FF`)
*   Background (Normal): Dark Charcoal (`#121217`)
**타이포그래피:** 모노스페이스 폰트 필수 적용 (예: 'Source Code Pro' 또는 유사 계열)

### ⚙️ Stage 1: 초기 데이터 입력 및 시스템 진입 (Baseline State)

| 요소 | 상세 스펙 | 애니메이션/인터랙션 지침 |
| :--- | :--- | :--- |
| **UI 레이아웃** | Fixed-Grid 기반의 간결하고 기능적인 형태. 필드와 그래프는 '진단 모듈' 형태로 분리 배치. | 기본 상태에서는 미묘한 전력 흐름(Low-opacity blue line)이 UI 요소들을 연결하며, 시스템이 작동 중임을 은유적으로 보여준다. |
| **입력 과정** | 사용자가 데이터를 입력할 때마다 해당 필드에 작은 녹색 `[OK]` 사인 또는 파동(Waveform) 애니메이션을 발생시킨다. | 데이터가 수집될 때마다 미세한 '데이터 픽셀'이 화면의 중앙 시스템 코어(가상의 프로세서 아이콘 등)로 흡수되는 애니메이션을 적용한다. (Easing: `cubic-bezier(.25,.46,.45,1)`) |
| **전환 트리거** | 마지막 입력 필드 제출 버튼 클릭 시. | 화면 전체에 잠시 동안의 블랙아웃(Blackout) 후, 시스템 부팅 사운드와 함께 'Diagnosis Initiated' 텍스트가 글리치 효과를 거쳐 나타난다. (Duration: 500ms). |

### ⚡ Stage 2: 시스템 경고 오버레이 시퀀스 (System Overload Alert)

**[핵심 난이도 구간]** 이 단계는 사용자의 집중력을 극대화하고 위기감을 최고조로 끌어올리는 것이 목표입니다.

#### A. 플래시 패턴 및 색상 변화 사양 (The Warning Escalation)
1.  **Level 1: 미세 오류 감지 (Initial Glitch)**
    *   **트리거:** 시스템 코어가 데이터를 처리하며 처음으로 임계값을 벗어난 지표가 포착될 때.
    *   **시각 효과:** 화면 전체에 걸쳐 낮은 주파수(5Hz)의 **Cyan/Blue Shift 플래시**를 발생시킨다. 텍스트와 그래프 가장자리에 미세한 `VHS 노이즈` 또는 `글리치 아티팩트`가 추가된다.
    *   **사운드:** '삐-익' 하는 짧고 불안정한 고주파음(High-pitched whine).
2.  **Level 2: 경고 임계값 초과 (System Warning)**
    *   **트리거:** 특정 지표(예: Context Drain Bar)가 빨간색 영역에 진입할 때.
    *   **시각 효과:** 플래시 주파수가 상승하며, 배경의 모든 네온 라인 요소들이 점진적으로 **Neon Red (`#FF3B30`)**로 변환된다 (Transition Time: 1s). 플래시는 2Hz 간격으로 빨간색과 어둠을 교차하는 패턴이 된다.
    *   **사운드:** 낮은 주파수의 '웅-' 하는 불안정한 드론 사운드(Drone Sound)가 배경에 깔린다.
3.  **Level 3: 시스템 과부하 (CRITICAL OVERLOAD)**
    *   **트리거:** 모든 주요 지표가 동시에 임계점을 벗어날 때.
    *   **시각 효과:** **최대 주파수 플래싱 (10~15Hz)**이 Neon Red로 발생한다. 화면 중앙에 'SYSTEM ALERT: CRITICAL OVERLOAD' 배너가 글리치하며 강제 오버레이된다. 모든 위젯의 경계선(Border)이 과부하 상태를 나타내듯 짧게 번쩍인다 (Strobe Effect).
    *   **사운드:** 날카로운 사이렌 소리와 함께 사운드가 급격히 상승했다가, 갑자기 '시스템 다운'되는 듯한 컷오프 효과를 준다.

#### B. 데이터 연결 애니메이션 스펙 (Data Flow Connection)
1.  **메타포:** 단순히 선을 긋는 것이 아니라, **'정보 흐름의 전기적 신호(Electrical Signal)'**로 표현한다.
2.  **애니메이션 과정:** 원본 모듈 A의 값이 변동하여 모듈 B에 영향을 미칠 때, A와 B 사이의 데이터 연결 라인(선)이 다음과 같은 과정을 거친다:
    *   **(Start):** 얇은 Cyan/Blue 점들이 무작위로 생성되어 선을 따라 이동한다. (Particle Emitter)
    *   **(Flow:** 점들이 모여 전기적인 '파동' 형태를 그리며 빠르게 흐른다. 이 파동의 색상은 경고 레벨에 따라 Blue $\rightarrow$ Yellow $\rightarrow$ Red로 변화해야 한다.
    *   **(End):** 최종 목적지 위젯 (B)의 해당 데이터 포인트가 업데이트될 때, 파동이 터져 나가면서 데이터를 '업데이트'하는 시각적 효과(Bloom Effect)를 준다.

### 🚀 Stage 3: 진단 결과 페이지 전환 (Diagnosis Outcome Page Transition)

| 요소 | 상세 스펙 | 애니메이션/인터랙션 지침 |
| :--- | :--- | :--- |
| **전환 방식** | 갑작스러운 '재부팅(Reboot)' 느낌의 강제 화면 변환. 시스템 오류 메시지처럼 작동한다. | 모든 시각 요소가 빠르게 줌 아웃되면서, 화면이 노이즈와 함께 번쩍이는 글리치 효과를 일으킨다. 이후, 최종 결과 페이지의 메인 CTA 배너만 '깨끗한' 네온 레드 강조 상태로 부각된다. |
| **결과 제시** | 진단 결과를 단순 텍스트가 아닌, **'시스템 로그(System Log)'** 형태로 제공한다. (예: `[ERROR] Resource depletion detected in PFC Index.` ) | 각 경고 메시지/진단 항목은 마치 터미널 창에 코드가 한 줄씩 입력되는 것처럼 타이핑 효과(Typewriter Effect)를 적용하여 전문성을 높인다. |
| **최종 CTA 강조** | Mini-Module의 진단 과정이 끝났지만, *문제가 해결되지 않았음*을 명확히 인지시키는 것이 목적이다. | 최종 Call To Action (예: "Pro Solution Required") 버튼은 주변 요소와 분리되어 마치 시스템에 강제로 '설치'되는 듯한 팝업 애니메이션과 함께 나타나야 한다. 이 버튼의 Neon Red는 가장 채도가 높고, 빛나는(Glowing) 효과를 주어 시선이 집중되게 설계한다. |
