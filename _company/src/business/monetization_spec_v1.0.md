# 💰 셀브릿지 유료 서비스 결제 및 가치 명세 (Payment & Value Specification v1.0)

**작성 목적:** 개발팀(Developer)이 '구독 및 상태 관리 게이트웨이'를 구현할 때 필요한 최종 비즈니스 로직, 가격 구조, 사용자 제공 가치를 확정합니다.
**최종 목표:** 결제 성공 시 사용자의 인지적 불안감을 해소하는 것이 아니라, **문제 해결 과정에 깊숙이 관여하여 LTV를 극대화**하는 것.

---

## 1. [가격 책정 및 티어링 구조] (Pricing & Tiering)
기존의 3단계 구조(FREE → PRO → ENTERPRISE)는 유지하되, 각 단계별 **'제한 요소(Limitation)'를 명확히 정의**하여 상위 결제를 유도해야 합니다.

| 등급 | 가격 (KRW 기준) | 핵심 가치 제안 (UVP) | 주요 제한 요소 (Upsell Hook) | 근거 지표/KPI |
| :--- | :--- | :--- | :--- | :--- |
| **FREE** | ₩0 | Basic Diagnostic Scan: 표면적 오류 식별. 문제 인식의 시작점 제공. | - 최대 3개 패치 영역만 확인 가능. <br> - 실시간 데이터 연동 불가. <br> - 원인 분석이 '학술 키워드' 수준에 머무름. | 초기 유입, 결제 퍼널 진입률 (Conversion to PRO) |
| **PRO** | ₩19,900 / 월 | Stability Patch Kit: 가장 흔한 인지적 결함(Focus/Memory)에 대한 맞춤형 '패치 명령어' 제공. | - 전문 분야 제한 (학술/업무 효율성). <br> - AI 코칭 세션은 월 2회로 제한. <br> - B2B 통합 API 연동 불가. **(가장 많은 결제 유도)** | 핵심 수익원, ARPU 개선율 |

## 2. [결제 성공 시 사용자 제공 가치 명세] (Deliverables List on Success)
사용자가 결제를 완료했을 때 즉시 다운로드/접근 가능한 **'물리적 증거(Artifact)'**를 명확히 정의해야 합니다. 단순한 '서비스 이용권'은 가치가 낮습니다.

### 📌 PRO 구매 시 제공되는 Deliverables:
1.  **Stability Patch Kit (PDF):** 맞춤형 패치 명령어 및 플레이리스트 리스트. (`[근거: 현빈 검증된 지식]`)
2.  **개인화된 결함 보고서 (Diagnostic Report Snippet - PDF):** "귀하의 [Focus/Memory] 영역에서 발견된 구조적 취약점 3가지"에 대한 학술 용어 기반 설명. (`[근거: 지난 의사결정 로그]`)
3.  **코칭 세션 예약 권한:** 월 2회 온라인 컨설팅 슬롯 접근권 (상태 변경 로직 필수).

### 📌 ENTERPRISE 구매 시 제공되는 Deliverables:
1.  **System Overhaul Master Report (PDF):** 사용자의 전체 생애주기(LTV) 관점에서 분석된 '종합 구조적 결함 진단 보고서' (모든 분야 커버, 고난이도 학술 용어). (`[근거: 현빈 검증된 지식]`)
2.  **전용 API 연동 모듈 접근 권한:** 외부 시스템(ERP/CRM 등)과 셀브릿지진단 결과값을 실시간으로 통합할 수 있는 가상의 API 게이트웨이 접속 정보 및 초기 셋업 컨설팅 (B2B 핵심). (`[근거: 현빈 검증된 지식]`)
3.  **전담 구조 개선 매니저 배정:** 전용 계정과 높은 우선순위의 커뮤니케이션 채널 제공.

## 3. [개발팀 필수 연동 조건 및 아키텍처 요구사항] (Technical Integration Requirements)

### A. 결제 시스템 로직 (Payment Gateway Logic)
1.  **트랜잭션 수수료 반영:** 모든 구독/결제 트랜잭션은 **실시간으로 변동되는 수수료(Stripe/PayPal Fee)**를 고려하여 최종 청구 금액을 계산해야 합니다. (예: `FinalPrice = BasePrice + Tax - RefundableFee`).
2.  **지역 제한 및 통화:** 초기에는 KRW ($) 기반의 결제만 허용합니다. 만약 다른 지역으로 확장 시, 반드시 해당 국가의 VAT/세금 구조를 반영하는 **`TaxCalculator` 모듈**이 필요합니다. (`[추측: 글로벌 확장 대비]`)
3.  **구독 상태 관리:** `SubscriptionService`는 단순 결제 성공 외에, '무료 체험 기간 만료', '결제 실패로 인한 일시 정지(Suspended State)', '계정 탈퇴' 등 **4가지 이상의 상태 전이(State Transition)**를 원자적으로 처리해야 합니다. (`[근거: 같은 세션의 동료 에이전트 산출물]`)

### B. API 게이트웨이 구현 조건 (Gateway Implementation)
1.  **`POST /api/v1/purchase_state` 엔드포인트:** 이 엔드포인트는 단순 결제 성공 여부만 반환해서는 안 됩니다. **'결제 금액', '선택한 티어(PRO/ENTERPRISE)', 그리고 '구매 시점의 구조적 진단 보고서 ID'** 세 가지 정보를 반드시 포함하여 상위 로직에 전달해야 합니다. (`[근거: 같은 세션의 동료 에이전트 산출물]`)
2.  **`AuditLogger` 연동:** 결제 성공/실패 여부와 관계없이, 모든 상태 변화는 `AuditLogger`를 통해 **구조적 오류 코드(Structural Defect Code)**와 함께 기록되어야 합니다. 이는 나중에 법률 자문 또는 컨설팅 자료로 활용됩니다. (`[근거: 같은 세션의 동료 에이전트 산출물]`)
