# Video Signature Service (VSS) Technical Specification\n\n**Goal:** To apply time-based, cryptographically verifiable integrity patches to video files and generate robust metadata logs proving the patching process.\n\n## 1. API Architecture & Flow (Asynchronous Job Queue)\n\nVideo processing is computationally expensive and non-blocking. Therefore, a Job Submission/Polling architecture must be used.\n\n### A. Submit Job (Job Submission Endpoint)\n*   **Endpoint:** `POST /api/v1/video-signature/job`\n*   **Request Body (Input):**\n    ```json\n    {\n      \"userId\": \"UUID\", \n      \"originalVideoUrl\": \"s3://bucket-name/raw_video.mp4\", \n      \"signatureMetadataList\": [\n        {\n          \"timeStartSeconds\": 5.0,       // Required start time (float)\n          \"timeEndSeconds\": 8.0,         // Required end time (float)\n          \"requiredAuthorityId\": \"AUTHORITY-UUID\", \n          \"reasonCode\": \"NON_REPUDIATION_GAP\"\n        }\n      ],\n      \"callbackWebhookUrl\": \"https://your-service.com/webhooks/vss/complete\"\n    }\n    ```\n*   **Response (Success):** `{\"jobId\": \"JOB-UUID\", \"status\": \"QUEUED\", \"estimatedCompletionTime\": \"...\"}`\n\n### B. Check Status (Polling Endpoint)\n*   **Endpoint:** `GET /api/v1/video-signature/job/{jobId}`\n*   **Response:** `{\"jobId\": \"JOB-UUID\", \"status\": \"PROCESSING\" | \"COMPLETED\" | \"FAILED\", \"details\": \"Processing progress...\"}`\n\n## 2. Core Logic: Timecode & Overlay (The Proof)\n\nThe value lies not just in the overlay, but in the verifiable metadata.\n\n### A. Signature Patching Logic\n*   **Mechanism:** Utilize a dedicated video processing library (e.g., FFmpeg bindings) to composite visual elements at precise timecodes.\n*   **Overlay Content Contract:** The visible text must include professional terminology linking back to the system's authoritative diagnosis (e.g., `[SYSTEM PATCH: Non-Repudiation Gap Filled]`).\n*   **Failure Handling:** If the video format is incompatible, or the time range is invalid (`start >= end`), the job *must* fail gracefully with a specific error code and message.\n\n### B. Metadata Generation (The Immutable Record)\nThis JSON log file is the primary proof of work and must be stored alongside the processed video.\n\n*   **Required Fields:**\n    1. `jobId` (UUID)\n    2. `originalVideoUrl`/`originalVideoHash` (SHA-256 of source)\n    3. `processedVideoUrl`/`finalVideoHash` (SHA-256 of output)\n    4. `processingTimestamp`: Current UTC time.\n    5. `appliedSignatures[]`: 배열 형태의 적용된 모든 서명 정보 (UUID, Timecode Range, ReasonCode).\n*   **Validation:** The system must cryptographically sign this `metadata.json` file using a private key to ensure its integrity upon retrieval.\n\n## 3. Scalability and Optimization\n\n1. **Job Queue System:** Implement RabbitMQ/Redis for decoupling the API layer from heavy processing tasks.\n2. **Worker Microservice:** Isolate video encoding, hashing, and metadata logging into a dedicated, horizontally scalable microservice (`VSS_Worker`).\n3. **Storage Optimization:** Use S3 Intelligent Tiering to manage costs; only high-priority/recent jobs need hot storage access.\n
