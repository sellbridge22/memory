2. **System Failure Narrative:** 사용자가 '시스템적 결함' 상태에 빠진 경험을 시각적으로 제공해야 합니다.
3. **Developer Utility:** 각 컴포넌트는 `State`와 `Props` 기반으로 분리되어 재사용 가능하도록 설계됩니다.

## 🧱 Component Definitions 및 상태별 스펙

### 1. [Context Drain Bar] (상태 추적 컴포넌트)
*   **기능:** 사용자의 인지 자원 고갈 정도를 시각화하여 불안감을 유도합니다.
*   **위치:** 화면 좌측 상단 또는 우측 하단의 HUD 형태로 고정 배치.
*   **상태 (State):** `Normal` $\rightarrow$ `Warning` $\rightarrow$ `Critical`

| State | Color/Gradient | 애니메이션 및 로직 | 개발자 참고 사항 |
| :--- | :--- | :--- | :--- |
| **Normal** | `#00FFFF` (Cyan Blue) | 느린 하강 속도(Slow Decay). 1분당 5% 감소. | `linear-easing` 적용 필수. |
| **Warning** | 오렌지 계열 (`#FF8C00`) | 감소 속도가 미세하게 빨라지고, 주변 그리드에 낮은 주파수의 깜빡임(`Flicker`) 발생. | Context Drain Rate가 25% 이하로 떨어졌을 때 트리거. |
| **Critical** | `#FF0033` (Neon Red) | 감소 속도가 급격히 빨라지고, 전체 배경에 네온 레드 노이즈 패턴(Noise Pattern Overlay)이 오버레이됨. | `Blink Rate: 8Hz`. 이 상태 도달 시 **[SYSTEM OVERLOAD Modal]** 발동 조건 충족. |

### 2. [PFC Index Meter] (학술적 지표 컴포넌트)
*   **기능:** 심리적 피로도 비용(Psychological Fatigue Cost Index)을 계기판 형태로 표시하며, 사용자가 자신의 문제를 '시스템 오류'로 인식하게 만듭니다.
*   **위치:** 화면 중앙 또는 측면에 메인 게이지 컴포넌트로 배치.
*   **상태 (State):** `Stable` $\rightarrow$ `Elevated` $\rightarrow$ `Critical`

| State | Visual Element | 애니메이션 및 로직 | 개발자 참고 사항 |
| :--- | :--- | :--- | :--- |
| **Stable** | 중앙 계기판(Gauge) 스타일. 초기 수치 (예: 75%) 표시. | 미세하고 불규칙한 떨림(`Jitter`) 애니메이션 적용. | `Amplitude`가 1-2px 수준의 무작위 오프셋을 가져야 자연스러움. |
| **Elevated** | 게이지 바늘이 빨간색 영역으로 진입하며, '주의' 경고 문구 출력. | 데이터 수집 과정 중 특정 복잡한 개념(예: Context Switching)에 노출될 때마다 임계점 상승. | `Transition Time`: 0.5초 이내의 급격한 변화가 필요함. |
| **Critical** | 게이지 전체가 네온 레드(`Primary_Alert`)로 가득 차고, 주변 UI 요소에 강한 떨림(Shake Effect)이 적용됨. | 경고음과 함께 `System Overload` 애니메이션을 동반하며 멈춤. | 이 수치가 임계점(예: 95%) 초과 시 **[SERVICE REQUIRED Modal]** 발동 조건 충족. |

### 3. [SYSTEM OVERLOAD] Modal (경고 및 전환 컴포넌트)
*   **기능:** Mini-Module 진단 과정 중, 사용자의 인지적 한계 또는 구조적 결함을 강렬하게 경고합니다. 콘텐츠의 클라이맥스이자 제품 필요성을 주입하는 장치입니다.
*   **발동 조건:** Context Drain Bar가 Critical에 도달하거나, PFC Index Meter가 임계점 초과 시 (`[근거: sessions/2026-05-13T07:56]`)
*   **디자인 스펙 (Mid-Fi):**
    *   **배경:** 전체 화면을 덮는 Semi-Transparent Black Overlay.
    *   **애니메이션:** 시작 시, **글리치 스터터(Glitch Stutter)** 필터를 강하게 적용하며 화면이 깨지는 듯한 효과로 진입합니다. (네온 레드/사이언 블루 노이즈 폭발) `[근거: sessions/2026-05-13T13:45]`
    *   **메시지:** 중앙에 거대한 네온 레드 타이포그래피로 **`WARNING: Structural Defect Detected`**가 점멸합니다. (Blink Rate 8Hz) `[근거: sessions/2026-05-07T05:40]`
    *   **반응:** 이 모달이 활성화되는 동안, 모든 배경 데이터 흐름(Graph)은 일시적으로 정지하고 빨간색으로 왜곡되어 보여야 합니다.

### 4. [Service Required] Modal (최종 CTA 컴포넌트)
*   **기능:** Mini-Module의 진단 과정이 끝난 후, 사용자가 스스로 '외부 솔루션(셀브릿지 Pro)'이 필요하다는 결론에 도달하게 만듭니다.
*   **발동 조건:** 모든 데이터 수집 및 분석 완료 (최종 단계).

## 📄 Mini-Module 디자인 시스템 컴포넌트 라이브러리 브리프 (v1.0)

본 가이드는 Mini-Module의 모든 인터랙션 요소가 따르는 공통적인 시각적 언어(Visual Language)와 기술 구현 지침을 제공합니다. 전체 시스템은 **Cinematic Industrial Drama** 톤과 **System Error Aesthetic**를 유지해야 합니다.

### I. 색상 변수 정의 (CSS Variables & Palette)

모든 컴포넌트의 색상은 이 네 가지 기본 변수에 의존하며, 이는 `root` 또는 `:root`에 선언되어야 합니다.

| 명칭 | 용도 | Hex Code | CSS Variable |
| :--- | :--- | :--- | :--- |
| **Primary Alert** (경고) | 오류 발생, Critical State 강조 | `#FF0033` (네온 레드) | `--color-alert-primary` |
| **Secondary Info** (정보) | 성공 상태, 데이터 흐름 표시 | `#00FFFF` (사이언 블루) | `--color-info-secondary` |
| **Background/Deep Black** | 메인 배경색, 시스템 깊이 표현 | `#1A1A2E` (딥 네이비 블랙) | `--color-bg-deep` |
| **Text/Primary** | 기본 텍스트 색상 | `#E0E0FF` (밝은 연보라) | `--color-text-primary` |

### II. 컴포넌트별 상세 스펙 (Atomic Components)

#### 1. [Button] 버튼 컴포넌트
*   **목표:** 사용자의 액션 유도 및 시스템 상태를 명확하게 반영.
*   **스타일:** 모든 버튼은 모서리가 약간 둥글고(Border Radius: 4px), 배경에 미세한 노이즈 필터가 깔린 듯한 질감을 가집니다.

| 상태 | 시각적 피드백 (Visual Feedback) | 기술 스펙 (Technical Specs) |
| :--- | :--- | :--- |
| **Default** (활성) | `background-color: var(--color-info-secondary);` 텍스트는 `--color-bg-deep`에 대비되어 시인성이 높아야 합니다. | `:hover`: 배경색이 네온 레드(`--color-alert-primary`)로 미세하게 플래시합니다. (Transition: `background-color 0.2s ease-in-out`). |
| **Disabled** (비활성) | 버튼 전체에 낮은 투명도의 검은 오버레이(Opacity: 0.4)를 적용하며, 텍스트와 배경색을 어둡게 만듭니다. | `[disabled]`: `cursor: not-allowed;` 애니메이션 효과가 없음. CSS 변수 `--color-text-primary` 값을 `#555588`로 오버라이드하여 사용합니다. |
| **Loading** (처리 중) | 버튼 내용이 'Processing...' 텍스트와 함께 회전하는 스피너로 대체됩니다. 배경색은 연한 사이언 블루가 유지됩니다. | `[loading]`: 클릭 불가 상태(Disabled와 동일). 내부 스피너는 *Loading Spinner* 컴포넌트를 사용합니다. |

#### 2. [Input Field] 입력 필드 컴포넌트
*   **목표:** 사용자 입력을 받고, 시스템과의 상호작용에 대한 즉각적인 피드백 제공.
*   **스타일:** 기본적으로 배경은 `--color-bg-deep`와 유사한 어두운 톤을 유지하며, 테두리는 미세하게 네온 사이언 블루 빛이 감도는 형태입니다.

| 상태 | 시각적 피드백 (Visual Feedback) | 기술 스펙 (Technical Specs) |
| :--- | :--- | :--- |
| **Focus** (포커스) | 입력 필드의 테두리(Border) 전체에 사이언 블루(`--color-info-secondary`)가 아닌, **글로우 효과(Box Shadow)**를 줍니다. | `focus:after`: `box-shadow: 0 0 8px var(--color-info-secondary);` (Diffusion Blur 적용). 포커스 시 미세한 전력 흐름(Power Flow) 애니메이션이 추가됩니다. |
| **Error** (오류) | 테두리 전체가 네온 레드(`--color-alert-primary`)로 변하고, 필드 아래에 붉은색 경고 메시지 라벨이 나타납니다. | `[aria-invalid="true"]`: `border-color: var(--color-alert-primary);`와 함께 애니메이션으로 **깜빡임 효과(Blink)**를 적용합니다. |

#### 3. [Loading Spinner] 로딩 스피너 컴포넌트
*   **목표:** 백그라운드 처리 중임을 시스템적으로 알림. 단순한 회전이 아닌, '데이터 흐름'의 느낌을 주어야 합니다.
*   **애니메이션 스펙 (The Data Stream Loop):**
    1.  **구조:** 3개의 평행한 사각형(`<div>`)으로 구성됩니다.
    2.  **로직:** 각 사각형은 독립적으로 **불규칙한 속도(Randomized Delay)**로 왼쪽에서 오른쪽으로 움직이며, 마치 데이터 패킷이 흐르는 것처럼 보입니다.
    3.  **색상/효과:** 사이언 블루(`--color-info-secondary`)를 사용하며, 이동하는 사각형의 끝부분에 미세한 `Trail Glow` (Box Shadow)가 따라다닙니다.

#### 4. [Error Modal] 시스템 에러 모달 컴포넌트
*   **목표:** 핵심 플로우에서 치명적인 결함이나 API 실패 시 사용자에게 강렬하게 경고하는 최종 단계.
*   **트리거 조건:** ① `Context Drain Bar`가 Critical Level 도달, ② `PFC Index Meter`가 임계점 초과, ③ 백엔드 API 호출 실패 (500/4xx 에러).
*   **인터랙션 스펙:**
    1.  **진입 효과:** 모달이 나타나기 직전, 화면 전체에 **강한 글리치 스터터(Glitch Stutter)** 필터를 0.2초간 강하게 적용합니다. (네온 레드/사이언 블루 노이즈 폭발) [근거: sessions/2026-05-13T13:45]
    2.  **메인 경고창:** 모달 중앙에 **`SYSTEM OVERLOAD`** 타이포그래피가 네온 레드로 점멸(Blink Rate 8Hz)하며 나타납니다. [근거: sessions/2026-05-13T09:41]
    3.  **메시지 구성:** 경고 문구는 학술적 용어와 결합되어야 합니다 (예: "WARNING: Structural Defect Detected due to Cognitive Overload").

### III. 시스템 통합 요약 및 개발 가이드라인

*   **애니메이션 공통 지침:** 모든 상태 변화 애니메이션에는 **`ease-in-out`** 트랜지션을 기본으로 사용하며, 속도감은 느리고 신중하게(Slow Decay) 느껴져야 합니다.
*   **폰트 시스템:** 텍스트는 `Inter` 또는 모노스페이스 계열의 기술적인 느낌을 주는 폰트를 사용합니다. (Bold/Semi-bold만 강조색으로 활용).

## 1. Overview
*   **Goal:** Communicate the structured process of Diagnosis $\to$ Failure Detection $\to$ Solution Necessity.
*   **Format:** 9:16 Aspect Ratio (Vertical Video).
*   **Aesthetic:** Cinematic Industrial Drama / System Overload.

## 2. Color Palette & Usage
*   **Primary Alert (Danger):** `#FF0033` (Neon Red) - Use for failure states, warnings, and CTA focus points.
*   **Secondary Info (System):** `#00FFFF` (Cyan Blue) - Use for normal data display, stable metrics, and system grid lines.
*   **Base:** `#1A1A2E` (Deep Navy/Black) - Background color.

## 3. Key Components & Specifications
### A. Context Drain Bar (Continuous Element)
*   **Location:** Top edge of the screen (Fixed position).
*   **Initial State:** Cyan Blue, full width (e.g., `width: 100vw; height: 4px;`).
*   **Animation Spec:** Slow decay rate (`linear-timing` function recommended). Must loop continuously throughout Step 1 & 2.
*   **Critical Trigger:** When the bar drops below 30% width, it must change color to `#FF0033` and trigger a subtle screen flicker effect.

### B. PFC Index Meter (Interactive Element)
*   **Location:** Mid-screen, slightly off-center. Gauge/Dial style.
*   **Initial State:** Visible only during Step 2. Initial value should be high (e.g., 75%).
*   **Animation Spec:** Must have a 'micro-vibration' or 'jitter' effect applied to the gauge face, simulating instability.
*   **Critical Trigger:** When the needle crosses the threshold line, the meter must flash red (`#FF0033`) and emit a visible digital ripple effect.

### C. [SYSTEM OVERLOAD] Modal (Full-Screen Overlay)
*   **Trigger:** Step 2 begins.
*   **Visuals:** Semi-transparent black overlay with intense noise/static pattern applied.
*   **Text Animation:** "WARNING: Structural Defect Detected" must appear using a character-by-character, flickering neon red text effect (8Hz Blink Rate).

### D. [SERVICE REQUIRED] Modal (Final CTA)
*   **Trigger:** Step 3 conclusion.
*   **Visuals:** Deep black background with heavy red saturation filter applied.
*   **Text Animation:** "SYSTEM FAILURE" must appear in massive, impactful typography, accompanied by a final, powerful glitch flash sequence.
*   **CTA Button:** Must be the only brightly colored element (e.g., Cyan Blue outline on a Red background) to direct focus.
