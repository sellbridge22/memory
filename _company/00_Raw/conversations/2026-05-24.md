# Agent Performance Optimization Workflow

Systematic improvement of existing agents through performance analysis, prompt engineering, and continuous iteration.

[Extended thinking: Agent optimization requires a data-driven approach combining performance metrics, user feedback analysis, and advanced prompt engineering techniques. Success depends on systematic evaluation, targeted improvements, and rigorous testing with rollback capabilities for production safety.]

## Use this skill when

- Improving an existing agent's performance or reliability
- Analyzing failure modes, prompt quality, or tool usage
- Running structured A/B tests or evaluation suites
- Designing iterative optimization workflows for agents

## Do not use this skill when

- You are building a brand-new agent from scratch
- There are no metrics, feedback, or test cases available
- The task is unrelated to agent performance or prompt quality

## Instructions

1. Establish baseline metrics and collect representative examples.
2. Identify failure modes and prioritize high-impact fixes.
3. Apply prompt and workflow improvements with measurable goals.
4. Validate with tests and roll out changes in controlled stages.

## Safety

- Avoid deploying prompt changes without regression testing.
- Roll back quickly if quality or safety metrics regress.

## Phase 1: Performance Analysis and Baseline Metrics

Comprehensive analysis of agent performance using context-manager for historical data collection.

### 1.1 Gather Performance Data

```
Use: context-manager
Command: analyze-agent-performance $ARGUMENTS --days 30
```

Collect metrics including:

- Task completion rate (successful vs failed tasks)
- Response accuracy and factual correctness
- Tool usage efficiency (correct tools, call frequency)
- Average response time and token consumption
- User satisfaction indicators (corrections, retries)
- Hallucination incidents and error patterns

### 1.2 User Feedback Pattern Analysis

Identify recurring patterns in user interactions:

- **Correction patterns**: Where users consistently modify outputs
- **Clarification requests**: Common areas of ambiguity
- **Task abandonment**: Points where users give up
- **Follow-up questions**: Indicators of incomplete responses
- **Positive feedback**: Successful patterns to preserve

### 1.3 Failure Mode Classification

Categorize failures by root cause:

- **Instruction misunderstanding**: Role or task confusion
- **Output format errors**: Structure or formatting issues
- **Context loss**: Long conversation degradation
- **Tool misuse**: Incorrect or inefficient tool selection
- **Constraint violations**: Safety or business rule breaches
- **Edge case handling**: Unusual input scenarios

### 1.4 Baseline Performance Report

Generate quantitative baseline metrics:

```
Performance Baseline:
- Task Success Rate: [X%]
- Average Corrections per Task: [Y]
- Tool Call Efficiency: [Z%]
- User Satisfaction Score: [1-10]
- Average Response Latency: [Xms]
- Token Efficiency Ratio: [X:Y]
```

## Phase 2: Prompt Engineering Improvements

Apply advanced prompt optimization techniques using prompt-engineer agent.

### 2.1 Chain-of-Thought Enhancement

Implement structured reasoning patterns:

```
Use: prompt-engineer
Technique: chain-of-thought-optimization
```

- Add explicit reasoning steps: "Let's approach this step-by-step..."
- Include self-verification checkpoints: "Before proceeding, verify that..."
- Implement recursive decomposition for complex tasks
- Add reasoning trace visibility for debugging

### 2.2 Few-Shot Example Optimization

Curate high-quality examples from successful interactions:

- **Select diverse examples** covering common use cases
- **Include edge cases** that previously failed
- **Show both positive and negative examples** with explanations
- **Order examples** from simple to complex
- **Annotate examples** with key decision points

Example structure:

```
Good Example:
Input: [User request]
Reasoning: [Step-by-step thought process]
Output: [Successful response]
Why this works: [Key success factors]

Bad Example:
Input: [Similar request]
Output: [Failed response]
Why this fails: [Specific issues]
Correct approach: [Fixed version]
```

### 2.3 Role Definition Refinement

Strengthen agent identity and capabilities:

- **Core purpose**: Clear, single-sentence mission
- **Expertise domains**: Specific knowledge areas
- **Behavioral traits**: Personality and interaction style
- **Tool proficiency**: Available tools and when to use them
- **Constraints**: What the agent should NOT do
- **Success criteria**: How to measure task completion

### 2.4 Constitutional AI Integration

Implement self-correction mechanisms:

```
Constitutional Principles:
1. Verify factual accuracy before responding
2. Self-check for potential biases or harmful content
3. Validate output format matches requirements
4. Ensure response completeness
5. Maintain consistency with previous responses
```

Add critique-and-revise loops:

- Initial response generation
- Self-critique against principles
- Automatic revision if issues detected
- Final validation before output

### 2.5 Output Format Tuning

Optimize response structure:

- **Structured templates** for common tasks
- **Dynamic formatting** based on complexity
- **Progressive disclosure** for detailed information
- **Markdown optimization** for readability
- **Code block formatting** with syntax highlighting
- **Table and list generation** for data presentation

## Phase 3: Testing and Validation

Comprehensive testing framework with A/B comparison.

### 3.1 Test Suite Development

Create representative test scenarios:

```
Test Categories:
1. Golden path scenarios (common successful cases)
2. Previously failed tasks (regression testing)
3. Edge cases and corner scenarios
4. Stress tests (complex, multi-step tasks)
5. Adversarial inputs (potential breaking points)
6. Cross-domain tasks (combining capabilities)
```

### 3.2 A/B Testing Framework

Compare original vs improved agent:

```
Use: parallel-test-runner
Config:
  - Agent A: Original version
  - Agent B: Improved version
  - Test set: 100 representative tasks
  - Metrics: Success rate, speed, token usage
  - Evaluation: Blind human review + automated scoring
```

Statistical significance testing:

- Minimum sample size: 100 tasks per variant
- Confidence level: 95% (p < 0.05)
- Effect size calculation (Cohen's d)
- Power analysis for future tests

### 3.3 Evaluation Metrics

Comprehensive scoring framework:

**Task-Level Metrics:**

- Completion rate (binary success/failure)
- Correctness score (0-100% accuracy)
- Efficiency score (steps taken vs optimal)
- Tool usage appropriateness
- Response relevance and completeness

**Quality Metrics:**

- Hallucination rate (factual errors per response)
- Consistency score (alignment with previous responses)
- Format compliance (matches specified structure)
- Safety score (constraint adherence)
- User satisfaction prediction

**Performance Metrics:**

- Response latency (time to first token)
- Total generation time
- Token consumption (input + output)
- Cost per task (API usage fees)
- Memory/context efficiency

### 3.4 Human Evaluation Protocol

Structured human review process:

- Blind evaluation (evaluators don't know version)
- Standardized rubric with clear criteria
- Multiple evaluators per sample (inter-rater reliability)
- Qualitative feedback collection
- Preference ranking (A vs B comparison)

## Phase 4: Version Control and Deployment

Safe rollout with monitoring and rollback capabilities.

### 4.1 Version Management

Systematic versioning strategy:

```
Version Format: agent-name-v[MAJOR].[MINOR].[PATCH]
Example: customer-support-v2.3.1

MAJOR: Significant capability changes
MINOR: Prompt improvements, new examples
PATCH: Bug fixes, minor adjustments
```

Maintain version history:

- Git-based prompt storage
- Changelog with improvement details
- Performance metrics per version
- Rollback procedures documented

### 4.2 Staged Rollout

Progressive deployment strategy:

1. **Alpha testing**: Internal team validation (5% traffic)
2. **Beta testing**: Selected users (20% traffic)
3. **Canary release**: Gradual increase (20% → 50% → 100%)
4. **Full deployment**: After success criteria met
5. **Monitoring period**: 7-day observation window

### 4.3 Rollback Procedures

Quick recovery mechanism:

```
Rollback Triggers:
- Success rate drops >10% from baseline
- Critical errors increase >5%
- User complaints spike
- Cost per task increases >20%
- Safety violations detected

Rollback Process:
1. Detect issue via monitoring
2. Alert team immediately
3. Switch to previous stable version
4. Analyze root cause
5. Fix and re-test before retry
```

### 4.4 Continuous Monitoring

Real-time performance tracking:

- Dashboard with key metrics
- Anomaly detection alerts
- User feedback collection
- Automated regression testing
- Weekly performance reports

## Success Criteria

Agent improvement is successful when:

- Task success rate improves by ≥15%
- User corrections decrease by ≥25%
- No increase in safety violations
- Response time remains within 10% of baseline
- Cost per task doesn't increase >5%
- Positive user feedback increases

## Post-Deployment Review

After 30 days of production use:

1. Analyze accumulated performance data
2. Compare against baseline and targets
3. Identify new improvement opportunities
4. Document lessons learned
5. Plan next optimization cycle

## Continuous Improvement Cycle

Establish regular improvement cadence:

- **Weekly**: Monitor metrics and collect feedback
- **Monthly**: Analyze patterns and plan improvements
- **Quarterly**: Major version updates with new capabilities
- **Annually**: Strategic review and architecture updates

Remember: Agent optimization is an iterative process. Each cycle builds upon previous learnings, gradually improving performance while maintaining stability and safety.

## 🚨 에이전트 성능 저하 패턴 및 실패 모드 분석 (Top 5)

### 카테고리 1: 기술 스택/리소스 관리 불안정성 (Technical Instability & Resource Management)
가장 빈번하게 관찰되는 오류 유형으로, LLM 호출이나 API 사용 과정에서 발생하는 시스템적 제약에 대한 대응 부족입니다. 이는 모델의 성능 자체를 의심하기보다, **'도구(Tool)'와 '자원(Resource)' 관리 측면**에서 접근해야 합니다.
*   **대표 실패 사례 1 (Context Length 초과):** 복잡한 목표 정의 및 상세 지침이 누적되면서 컨텍스트 창을 초과하여 이전의 중요한 전제 조건이나 제약 사항을 간헐적으로 무시하는 현상 발생. [근거: 여러 세션에서 반복된 Context Length 확보 요구]
*   **대표 실패 사례 2 (Model Selection 오류):** 작업 난이도에 비해 모델 크기를 작게 선택하거나, API 권한/기간 설정을 재확인하지 않아 데이터 수집 또는 복잡한 추론 과정 자체가 중단되는 경우. [근거: 다수 로그에서 Model Size 조정 및 API 점검 지시 반복]
*   **대표 실패 사례 3 (Tool Misuse):** 여러 에이전트가 동시에 작동하는 환경에서, 특정 작업에 필요한 도구(Tool)를 호출할 때 최적의 순서나 조합을 찾지 못하고 비효율적이거나 잘못된 도구를 사용하게 되는 경우. [근거: 'agent-orchestration-improve-agent' 스킬 자체가 필요함]

### 카테고리 2: 컨셉 및 트렌드 과부하 (Conceptual Overload & Scope Creep)
셀브릿지가 추구하는 여러 전문 영역(심리학, 기술, 드라마, 아날로그 감성 등)의 키워드가 너무 많이 결합되면서 콘텐츠가 어떤 핵심 메시지에 집중해야 할지 혼란을 겪는 패턴입니다.
*   **대표 실패 사례 1 (메시지의 분산):** '학술적 권위(Academic Authority)'와 '신비로운 드라마틱한 시스템 오류(System Failure)' 같은 상충되는 두 가지 톤이 동시에 강조되면서, 최종 메시지가 사용자에게 모호하게 전달됨. [근거: Self-RAG 및 지난 의사결정 로그의 다중 테마 혼합]
*   **대표 실패 사례 2 (앵커링 효과 오용):** 고가치/고난도 컨셉(ENTERPRISE)을 전면에 내세우는 것은 좋으나, 그 근거가 되는 '미니 모듈($4.99)'의 가치를 충분히 부각하지 못하고 전체 구조의 설득력을 떨어뜨리는 경우. [근거: Self-RAG 및 Mini-Module 리서치 지시]
*   **대표 실패 사례 3 (일관성 부족):** 특정 트렌드(예: Y2K 무드)를 반영하는 과정에서, 핵심 가치인 '인지 부하 관리'와 같은 전문적이고 진지한 주제의 맥락을 훼손하여 피상적인 콘텐츠로 전락할 위험. [근거: 레오/Instagram 에이전트 활동 로드맵 수립 기록]

### 카테고리 3: 데이터 근거 및 주장의 신뢰성 결핍 (Lack of Data Grounding & Validation)
주장하는 트렌드나 문제 인식이 '직관'이나 '개인적인 분석'에 의존할 때, 이를 뒷받침할 수 있는 객관적이고 측정 가능한 데이터가 부족하여 권위가 약화됩니다.
*   **대표 실패 사례 1 (근거의 일반론):** "현대인은 피로하다"와 같은 광범위하고 일반적인 주장만 반복하고, 이를 '시스템 과부하'라는 셀브릿지만의 독점적 프레임으로 구체적으로 수치화하지 못하는 경우. [근거: Researcher 개인 메모리 - 2026-05-07 데이터 요청]
*   **대표 실패 사례 2 (측정 가능한 Pain Point 누락):** 사용자에게 "집중력이 떨어진다"는 감정적 공감만 이끌어내고, 이를 **'오전 중 특정 앱 알림 확인 빈도'와 같이 측정 가능하고 구체적인 수치(Metric)**로 정의하지 못하는 경우. [근거: Mini-Module Pain Point 재수집 지시]
*   **대표 실패 사례 3 (출처의 비대칭성):** 콘텐츠에서 다룬 '사례'가 특정 산업이나 지역에만 국한되어 있는데, 이를 일반적인 시장 트렌드인 것처럼 포장하여 신뢰성을 떨어뜨리는 경우. [근거: 데이터 기반 분석 원칙 미준수 시 위험]

### 카테고리 4: 사용자 경험(UX)의 단일화 실패 (Failure to Standardize UX/Interaction)
디자인 시스템과 인터랙션이 매우 구체적이지만, 이 요소들이 다양한 플랫폼이나 콘텐츠에 일관되게 적용되지 못하면 브랜드 경험 자체가 파편화됩니다.
*   **대표 실패 사례 1 (애니메이션의 불규칙성):** '글리치 효과'를 필수적으로 넣기로 했으나, 영상의 종류(릴스, 웹페이지, 플레이리스트)나 내용에 따라 글리치 효과의 강도, 지속 시간 등이 일정하지 않은 경우. [근거: Designer 에이전트가 다수의 컴포넌트/플랫폼에서 일관성을 요구함]
*   **대표 실패 사례 2 (콜 투 액션(CTA)의 혼란):** 콘텐츠를 보는 목적(정보 습득, 공감, 구매 유도)에 따라 CTA가 너무 많거나, 너무 약한 경우. 예를 들어 "댓글로 질문하세요"와 "지금 $4.99 모듈을 사세요"가 동시에 강요되어 피로도를 높이는 경우. [근거: Instagram 및 로드맵 수립 기록]
*   **대표 실패 사례 3 (온보딩 과정의 복잡성):** 셀브릿지 서비스에 처음 진입하는 사용자가 '시스템 오류'라는 추상적인 개념을 이해하고, 어떤 기능을 어디서 써야 할지 직관적으로 파악하기 어려운 구조. [근거: 신규 유저의 초기 이탈 지점 예측 필요]

### 카테고리 5: 프로세스 최적화 루틴 미흡 (Lack of Continuous Optimization Loop)
성공적인 작업물(Good Example)을 만들어낸 후, 그 성공 요인(Why this works)을 체계적으로 문서화하고 다음 단계의 '가장 효율적인 개선점'으로 활용하지 못하는 경우입니다.
*   **대표 실패 사례 1 (단순 복제):** 지난번 잘된 콘텐츠의 주제나 형식을 단순히 반복하여 재활용할 뿐, 근본적인 *시청자 문제 인식(Pain Point)*이나 *기술적 해결책*을 진화시키지 못하는 경우. [근거: 레오/Instagram 에이전트가 로드맵 수립만 하고 다음 단계를 구조적으로 제시하지 못함]
*   **대표 실패 사례 2 (최소 기능 구현에 대한 집착):** 완벽한 기능을 만들기 위해 너무 많은 시간을 소요하여, 시장의 즉각적인 수요 변화(Time-to-market)를 놓치고 뒤처지는 경우. [근거: Mini-Module과 같은 '패치 기반' 접근이 필요한 이유]
*   **대표 실패 사례 3 (A/B 테스트 부재):** 새로운 가설을 세우고도, 이를 검증하기 위한 체계적인 A/B 테스트나 사용자 그룹 분리가 없이 전체 시스템에 무작정 적용하여 리스크를 키우는 경우. [근거: 성능 최적화 워크플로우의 핵심 요소]

// CORE INTERACTIVITY & STATE MANAGEMENT LOGIC (디버깅 필수)
// 이 스크립트는 '시스템의 작동'을 시각적으로 증명해야 합니다.
// =======================================================

document.addEventListener('DOMContentLoaded', () => {
    const mainCtaBtn = document.getElementById('main-cta-btn');
    const purchaseBtn = document.getElementById('purchase-btn');
    const steps = document.querySelectorAll('.process-step');

    // 1. State Transition Button 로직 시뮬레이션 (진단 시작)
    mainCtaBtn.addEventListener('click', () => {
        console.log("✅ [SYSTEM LOG] User clicked Start Diagnosis. Initiating Phase 1.");
        alert(">> 시스템 진단 모듈 활성화: 다음 단계로 이동하여 데이터 입력을 시뮬레이션해주세요.");

        // 버튼 상태 변경 및 비활성화 (전환 완료 시)
        mainCtaBtn.setAttribute('data-state', 'disabled');
        mainCtaBtn.textContent = "진행 중... 데이터를 분석하는 중...";
        mainCtaBtn.style.cursor = 'default';

        // 2초 후, 다음 프로세스 단계로 전환 시뮬레이션 시작
        setTimeout(() => {
            updateProcessState(1); // Step 1을 완료 상태로 가정
            console.log("⚙️ [STATE CHANGE] Phase 1 -> Phase 2 Transition Successful.");
        }, 2000);
    });

    // 2. 프로세스 단계 업데이트 함수 (핵심 로직)
    function updateProcessState(targetStep = 2) {
        steps.forEach((step, index) => {
            const stepNum = index + 1;
            if (stepNum === targetStep) {
                // 현재 스텝 활성화 및 글리치 효과 부여
                step.classList.add('active');
                step.innerHTML = `<h3>[STAGE ${targetStep}] 데이터 분석 및 시스템 경고</h3><p>AI가 패턴을 인식하고, '위험도'를 계산합니다.</p>`;
            } else {
                // 나머지 스텝은 기본 상태로 복원
                step.classList.remove('active');
            }
        });

        // 3단계 전환 시뮬레이션 (최종 CTA 활성화)
        if (targetStep >= 2 && !purchaseBtn.hasAttribute('data-ready')) {
             console.log("✅ [SYSTEM LOG] Analysis complete. Pro Solution required.");
             purchaseBtn.setAttribute('data-ready', 'true');
             purchaseBtn.style.opacity = 1; // 구매 버튼 활성화
        }
    }

    // 3. 최종 CTA (구매) 로직
    purchaseBtn.addEventListener('click', () => {
        if (!purchaseBtn.hasAttribute('data-ready') && !confirm("⚠️ 경고: 진단 점수가 충분하지 않아 Pro 솔루션 구매가 필요합니다. 정말 진행하시겠습니까?")) {
            console.error("[SYSTEM ALERT] Purchase rejected by user.");
            alert("시스템이 필수 데이터 분석을 완료했습니다. 프로 솔루션을 통해 자동화된 완벽한 결과물을 얻으세요!");
        } else {
            alert("🚀 Pro Solution 구매 및 시스템 통합 모듈 활성화가 시작됩니다. 결제 API 호출 예정...");
        }
    });

});
